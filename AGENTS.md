# Verbal

Before modifying this app, read `docs/SHARED_PWA_RULES.md` (reviewed copy of the shared PWA rules, including the 2026-11-01 shared controls/deploy and native language pull-down decisions), then README.md and docs/VERIFICATION.md. The original shared document's central-toolbox-only rules do not change Verbal's own file layout. No missing sibling-path dependency is required.

- Repository on the user's Mac: `/Users/nfp/github/pwa/verbal`. Production destination: `https://verbal.basecentral.link`. Do not publish production unless explicitly instructed.
- Static HTML/CSS/JavaScript in `public/`. No build step, npm, PHP, account, telemetry or remote runtime dependency.
- Support iPhone 6 / iOS 12.5.x / Safari 12. Keep startup code parseable; feature-detect optional APIs. Do not use dialog.showModal, replaceChildren, optional chaining, nullish coalescing or File.text.
- UI languages: pt-PT and English, immediate switch without altering the Portuguese puzzle. Game vocabulary language and UI language are separate concerns. English word banks are not part of this release.
- Word lengths 4–8, six guesses for each. Correct occurrence counts for repeated letters. A separate daily answer for each length, midnight Europe/Lisbon. Do not reorder a released answer bank without versioning the daily algorithm and preserving saved games.
- Persist games, drafts and preferences in one app-scoped localStorage value. Lossless backup JSON `format: verbal`, `schema: 1`. Restore replaces, validates first and offers Restore preferences checked by default. Preserve storage after failed imports; guard stale writes across windows.
- Answer banks in words.js remain manually selected starting lists and their order is immutable. Accepted guesses in guesses.js are generated separately from pinned European Portuguese Hunspell sources in vendor/dictionary; keep the source revision, attribution, selected MPL-1.1 licence and reproducible build script. Plurals and conjugated verbs are allowed when present in the accepted list. Do not add guesses to the daily answer banks merely to expand validation. All entries must be complete words with the declared normalized length. Do not pad banks with truncated words or unverified fragments. Expand reviewed lists and keep answers a subset of accepted guesses.
- Shared SVG Settings gear followed by a native flag language select in top right. 44px target minimum for ordinary controls, page fits 320px, localized labels/errors, managed focus, non-color score cues. Use 2px control and 4px panel corners.
- Cache the complete release atomically at install; never auto-activate updates. Preserve old version caches while old tabs may use them. Bump app.js and sw.js VERSION together, run `python3 scripts/prepare-release.py`, and document cache retention. Verify each release asset hash before populating the offline cache.
- Public webroot receives only PUBLIC_FILES in scripts/deploy-profile.sh through the vendored shared Bash deployment engine. Run prepare-release.py to regenerate the private deploy-hashes.txt after runtime changes; deployment rejects stale hashes. Hosting configuration is optional and installed manually, never exposed under its source name. Pull-only host deploy; refuse dirty/ahead/detached sources and overlapping webroots, no reset/clean/stash/push/delete of unrelated files.
- Run `node scripts/test-core.cjs`, `node scripts/test-sw.cjs`, `python3 scripts/test-deploy.py`, JS syntax checks and relevant browser QA. Document actual evidence; physical iPhone 6 validation is still required.

## User play-screen decision — 2026-11-02

Keep all six attempt rows and an unwrapped three-row QWERTY keyboard visible together on phone portrait viewports. Compact the board and spacing while retaining readable letters. The on-screen keyboard has an explicit domain exception to the shared 44px minimum width: ten QWERTY keys fit 320px by using narrower widths; every key remains at least 44px tall. Ordinary controls retain 44×44px targets. Use a native length selector alongside mode controls to save a row. In extremely short/landscape or enlarged-text views, allow natural document scrolling rather than clipping controls or shrinking text below readable sizes. Do not wrap QWERTY keys into extra rows.
